# 실험 설계

모델만 교체하고 호출 경로·프롬프트·토큰 예산·채점 규칙은 전부 고정한다.
이 태스크는 **에이전트 프레임워크를 사용하지 않는다**(§1).

이 문서가 **플랫폼 제약과 채점 규칙의 단일 출처**다.
결과 해석은 [FINDINGS.md](./FINDINGS.md), 데이터셋은 [BENCHMARKS.md](./BENCHMARKS.md),
용어 정의는 [README.md](./README.md).

---

## 1. 에이전트 프레임워크 없이 API를 직접 호출한다

에이전트 프레임워크는 도구 호출이 실패하면 자동으로 재시도하고 응답을 수정한다.
이 실험이 측정하려는 것은 **도구 호출이 첫 시도에 규격대로 반환되는가**이므로,
프레임워크를 거치면 측정할 수 없다.

같은 저장소의 `mle-benchmark`는 이 계열 문제를 결과로만 관측했다 —
*"7 of 72 cells DNF'd — every one a harness/tool-conformance fault, not a modeling failure."*

부수적으로 모든 응답에 `usage`가 포함되어 **호출 단위 비용 산출이 가능하다**
([COST.md](./COST.md)).

## 2. 실행 전에 지원 기능을 확인한다 (1단계)

**이 단계가 다른 태스크와 구별되는 지점이다.**

일반적인 벤치마크는 "같은 프롬프트를 세 모델에 전달한다"로 공정성을 확보한다.
이 플랫폼에서는 그 전제가 성립하지 않는다. 실행 전에 지원 기능을 확인하고
결과를 산출물로 남긴다 (`probes/probe_capabilities.py`).

### 지원 기능 확인 결과 (2026-08-06)

`400`은 게이트웨이가 요청 자체를 거부한 경우다.

| 확인 항목 | Opus 5 | GPT-5.6-sol | GLM 5.2 |
|---|:---:|:---:|:---:|
| 단일 도구 호출 | 정상 | **400** | 정상 |
| 병렬 도구 호출 | 정상 | **400** | 정상 |
| 무관한 요청에 도구 미호출 | 정상 | **400** | 정상 |
| `tool_choice: required` / 특정 도구 지정 | 정상 | **400** | 정상 |
| 도구 결과를 대화에 포함해 재호출 | 정상 | **400** | 정상 |
| `response_format: json_object` | **400** | 정상 | 정상 |
| `response_format: json_schema` (strict) | 정상 | 정상 | 정상 |
| `reasoning_effort` | **400** | 정상 | 정상 |
| `thinking: {type: disabled}` | 정상 | **400** | 정상 |
| `temperature: 0` | **400** | **400** | 정상 |
| `seed` | **400** | 정상 | 정상 |

GPT-5.6-sol의 도구 사용 거부는 `reasoning_effort`를 **생략해도** 발생한다.
게이트웨이가 반환하는 메시지는 다음과 같다.

```
Function tools with reasoning_effort are not supported for gpt-5.6-sol in
/v1/chat/completions. To use function tools, use /v1/responses or set
reasoning_effort to 'none'.
```

**세 모델이 지원하는 파라미터 집합이 거의 겹치지 않는다.**
무엇을 고정하고 무엇을 모델별로 다르게 설정할지 명시적으로 정해야 한다.

### 세 모델에 공통으로 적용 가능한 설정이 없다

| | 도구 사용 + 추론 켬 | 도구 사용 + 추론 끔 |
|---|---|---|
| GPT-5.6-sol | HTTP 400 (chat/completions) → **Responses 경로에서만 가능** | 정상 |
| Opus 5 | 정상 | **응답 형식 오류** (§3.1) |
| GLM 5.2 | 정상 | 정상 |

어느 쪽으로 통일해도 한 모델에서 오작동이 발생한다. 따라서 실험 조건을 나눈다.

| | 실험 조건 A (설정 통일) | 실험 조건 B (모델별 최대 설정) |
|---|---|---|
| Opus 5 | `thinking: {type: disabled}` | `output_config: {effort: "high"}` |
| GPT-5.6-sol | `reasoning_effort: "none"` | **`/ai-gateway/codex/v1/responses`** + `reasoning.effort: "high"` |
| GLM 5.2 | `reasoning_effort: "none"` | `reasoning_effort: "high"` |
| 목적 | 모델 간 비교 | 실제 배포 시 성능 (**GPT-5.6-sol만 호출 경로가 다름**) |

> **Opus 5의 추론 강도 파라미터는 `output_config.effort`다.**
> 공식 문서가 안내하는 `thinking` / `budget_tokens` 조합은 HTTP 400을 반환한다.
> 게이트웨이 오류 메시지가 대안을 알려준다:
> *`Use "thinking.type.adaptive" and "output_config.effort"`*.

**실험 조건 A′(보정)**: Opus 5만 `thinking: {type: adaptive}`로 다시 실행한다.
이유는 §3.1.

## 3. 플랫폼 제약 — 오작동을 모델 성능으로 해석하지 않기 위해

### 3.1 Opus 5가 도구 호출을 본문 텍스트로 반환하는 경우

`tool_calls` 배열이 비어 있고 Anthropic 내부 표기법인 XML이 `content` 필드에
포함되어 반환되는 응답이 확률적으로 발생한다.
`finish_reason`은 `tool_calls`로 정상 표기된다.

```jsonc
{"finish_reason": "tool_calls",
 "message": {"tool_calls": [],
             "content": "<invoke name=\"get_weather\">\n<parameter name=\"city\">서울</parameter>\n</invoke>"}}
```

동일 요청 12회 반복 결과:

| 조건 | 정상 응답 | **형식 오류** |
|---|---:|---:|
| `thinking: {type: "disabled"}`, 게이트웨이 경로 | 4 | **8** |
| `thinking: {type: "disabled"}`, serving-endpoints 경로 | 5 | **7** |
| `thinking: {type: "adaptive"}` | **12** | 0 |
| **`claude-sonnet-5`** + `thinking: {type: "disabled"}` | **12** | 0 |

**호출 경로와 무관하고, Opus 5에만 나타나며, `thinking:adaptive`를 명시하지 않으면
발생한다.** 본 실험 2,310 호출에서도 재현됐다 —
`disabled` 135회 중 6회, `output_config.effort:high` 135회 중 1회, `adaptive` 0회.
추론 강도를 높이는 것만으로는 완전히 제거되지 않는다.

**1차 측정에서 Opus 5의 FC-1(가장 단순한 카테고리) 정확도가 0.760이었다.**
보정 조건(A′)에서는 0.920이었다. 실행 전에 지원 기능을 확인하지 않았다면
0.760을 모델 성능으로 보고했을 것이다.

### 3.2 `response_format`과 `tools`를 동시에 지정했을 때

| 모델 | 결과 |
|---|---|
| Opus 5 | **HTTP 400** — `Cannot specify both response_format and tools in the same request.` |
| GPT-5.6-sol | 200, **도구 호출 수행** (15/15) |
| GLM 5.2 | 200, **도구 호출 없음** + `{"answer": "서울의 날씨를 조회해 드리겠습니다."}` (**30/30**) |

**GLM 5.2의 동작은 오류 신호를 남기지 않는다.** 상태 코드는 200이고,
응답은 스키마 검증을 통과하며, 내용도 자연스럽다. 그러나 도구 호출은 실행되지 않았다.
상태 코드와 스키마 검증만 확인하는 파이프라인은 이 실패를 감지할 수 없다.
Opus 5의 HTTP 400은 지원하지 않는 조합임을 명시적으로 알린다.

### 3.3 추론 토큰은 출력 토큰에 포함된다

`reasoning_tokens`는 `completion_tokens`에 포함된 내역이며 별도 항목이 아니다.
따라서 과금 대상 출력 토큰은 `completion_tokens`이고 둘을 더하면 안 된다.
측정 근거와 산출식은 [COST.md](./COST.md).

### 3.4 `temperature`를 지정할 수 없다

Opus 5와 GPT-5.6-sol이 이 파라미터를 거부한다.
**온도를 0으로 고정해 출력을 재현 가능하게 만드는 표준 방법을 쓸 수 없다.**
따라서 반복 측정이 필요하다.

### 3.5 서버가 자동으로 추가하는 프롬프트의 양이 모델마다 3~13배 다르다

Databricks Foundation Model API REST 레퍼런스는 다음과 같이 명시한다.

> *"`prompt_tokens` includes all text added by our server."*

추가되는 양은 문서에 없다. 사용자 메시지를 바이트 단위로 고정하고
`tools` / `response_format`만 바꿔가며 측정했다
(`probes/probe_scaffolding_overhead.py`).

| 조건 | Opus 5 | GPT-5.6-sol | GLM 5.2 |
|---|---:|---:|---:|
| 기준 (도구·스키마 없음) | 44 | 33 | 39 |
| 도구 1개 추가 | **+402** | **+127** | +174 |
| 도구 16개 추가 | +2,142 | +562 | +1,344 |
| JSON 스키마 추가 | **+504** | **+39** | +149 |
| 도구 1개당 증가량 | **116** | **29** | 78 |

Opus 5와 GPT-5.6-sol의 **입력 토큰 단가가 동일**하므로, 이 토큰 차이가
그대로 비용 차이가 된다.

---

### 3.6 Opus 5가 `parameters`에 `type`이 없는 도구 정의를 거부한다

무인자 도구를 `{"parameters": {}}`로 정의하면 모델별로 동작이 갈린다.

| 모델 | 결과 |
|---|---|
| GPT-5.6-sol, GLM 5.2 | 정상 수용 |
| **Opus 5** | **HTTP 400** `tools.N.custom.input_schema.type: Field required` |

FunctionChat-Bench 606건 중 73건이 이 형태의 도구를 포함한다.
도구 호출 능력이 아니라 스키마 검증 엄격도의 차이이므로, 의미가 같은
`{"type": "object", "properties": {}}`로 정규화해 측정에서 제외했다
(`cases/build_fcb_cases.py`의 `normalize_tools`).

**다른 모델에서 동작하던 도구 정의를 Opus 5로 옮기면 HTTP 400이 발생할 수 있다.**
`parameters`에 `type`을 명시하면 해결된다.

## 4. 호출 경로 — `/serving-endpoints`는 서버 측 측정이 불가능하다

`system.ai_gateway.usage` 시스템 테이블의 24시간치 URL을 전수 집계한 결과,
**약 573만 행 중 `/serving-endpoints/` 경로가 0건**이었다. 전부 `/ai-gateway/*` 경로다.

공식 문서와도 일치한다. Track model usage 문서는 "Unity AI Gateway model service"만
다루며, 스키마 예시의 `url` 값도 `/ai-gateway/...`다.

→ **본 실험은 `/ai-gateway/mlflow/v1/chat/completions` 경로를 사용한다.**
세 모델 × (기본 / 도구 사용 / JSON 스키마) 9개 조합이 모두 정상 동작함을 확인했다.
이 경로를 사용하면 서버 측 `latency_ms`, `time_to_first_byte_ms`, `token_details`와
`Databricks-Ai-Gateway-Request-Tags`를 통한 호출 단위 귀속을 함께 얻을 수 있다.

### 시스템 테이블 조회 시 주의사항

| 주의사항 | 대응 |
|---|---|
| `destination_model` 값이 일정하지 않다 (`claude-opus-5`와 `Claude Opus 5`가 함께 존재) | **`destination_name`으로 집계**한다 |
| `endpoint_name`이 두 가지 형태로 존재한다 (게이트웨이형 / 서빙형). 한쪽만 필터하면 **약 40%가 누락**된다 | `endpoint_name`으로 필터하지 않는다 |
| 거부된 요청(4xx)도 행으로 기록되며 토큰 컬럼이 NULL이다 | 통계 산출 시 **`status_code = 200`으로 필터**한다 |

## 5. 데이터셋

자체 제작 케이스만으로는 변별력이 부족해 외부 공개 벤치마크 2종을 함께 쓴다.
전체 9,942 호출 중 63%가 외부 데이터다. 외부 데이터는 재배포하지 않고

이 저장소는 **도구 호출을 억제했는가만** 기계 채점하므로 원본 리더보드와 비교할 수 없다.

출처·변별력·선정 근거는 [BENCHMARKS.md](./BENCHMARKS.md).

## 6. 채점

**LLM 채점자를 사용하지 않는다.** 산출물이 JSON과 도구 호출이므로 프로그램으로
완전히 검증할 수 있다. 같은 저장소의 `image-text-performance`가 겪은 채점 오류
(응답 잘림, 점수 파싱 오탐, 실패 시 중간값으로 대체)를 구조적으로 회피한다.

### 실패를 유형별로 분류한다

| 유형 | 예 | 처리 |
|---|---|---|
| **인프라 오류** | 5xx · 429 · 타임아웃 · 토큰 만료 | 채점 제외 + 건수 보고 |
| **게이트웨이 거부** | HTTP 400 `Cannot specify both...` | 채점 제외 + **지원 여부로 기록** |
| **형식 오류** | JSON 파싱 실패 · 스키마 위반 · 정의되지 않은 도구 이름 | **0점** — 이것이 측정 대상이다 |
| **호출 판단 오류** | 호출해야 할 때 안 함 / 하지 말아야 할 때 함 | **별도 지표로 집계** |

### Function Calling 채점 — 선택적 파라미터 추가는 오답이 아니다

사전 점검에서 세 모델 모두 `get_weather(city="서울")`에 `unit="celsius"`를 추가했다.
스키마상 선택적 파라미터이고 enum에 정의된 값이므로 **정답으로 처리한다.**
이를 오답으로 처리하면 구문 구조 비교 방식의 알려진 취약점을 그대로 재현하게 된다
(관련 연구에서 오답의 70~90%가 모델이 아니라 채점 방식에서 비롯됐다는 보고가 있다).

채점 규칙:

- 정답에 정의된 키는 **전부 존재해야 하고 값이 일치해야** 한다
- 정답에 없지만 **스키마에 정의된 선택적 키는 허용**한다 (enum 위반이면 오답)
- 스키마에 없는 키는 **정의되지 않은 파라미터**로 오답 처리한다
- 병렬 호출은 **순서와 무관하게 1:1 대응**시켜 비교한다

### Structured Output 채점

`jsonschema` 라이브러리(Draft 2020-12)로 검증하고 필드 값을 대조한다.
1차 파싱(문자열 보정 없이)과 코드 블록 표기 제거 후 파싱을 구분해 집계한다.

### 지표

| 축 | 산출 방식 |
|---|---|
| 정확도 | 카테고리별 정답률 + **Wilson 95% 신뢰구간**. 구간이 겹치면 **차이를 확인할 수 없음**으로 판정 |
| 안정성 | **`pass^k = C(성공횟수, k) / C(시행횟수, k)`** — k회 시행이 **모두** 성공할 확률. "최소 1회 성공"을 뜻하는 `pass@k`와 다르다 |
| 호출 판단 | 도구 호출률 / 무관한 요청 시 미호출 / 되물음 / 임의 값 생성 / 도구 호출 누락을 분리 집계 |
| 비용 | 응답의 `usage` × 공시 DBU 단가 ([COST.md](./COST.md)) |

**반복 횟수는 5회.** `temperature`를 지정할 수 없으므로(§3.4) 반복이 필요하다.
평균 정확도와 `pass^5`의 차이가 반복 간 편차의 크기를 나타낸다.

## 7. 케이스 설계 — 일반적으로 알려진 한국어 난제는 제외했다

사전 점검에서 조사 제거, 만·억 단위 변환, NFD 정규화, 한자 표기 개체명,
음력 명절 날짜, 상대 요일, 한국어 enum 값이 **세 모델 모두 정답**이었다.
이런 항목으로 케이스를 구성하면 세 모델이 모두 100%인 표가 나온다.

실제로 차이가 나타나는 항목에 비중을 둔다.

| 트랙 | 카테고리 | 측정 대상 |
|---|---|---|
| **Function Calling** | FC-1 단일 도구 · FC-2 유사 도구 4개 중 선택 · FC-3 병렬 호출(한국어 접속조사) | 기본 능력과 변별력 |
| | **FC-5 무관한 요청** — 호출하지 않는가 · **FC-6 정보 부족** — 되묻는가 | 호출 판단 |
| | FC-7 제약 있는 인자(enum·날짜 형식) · FC-8 한국어 고유 표현(만·억 단위, 조사, 상대 날짜) | 정밀도 |
| | **FC-X `tools`와 `response_format` 동시 지정** | 오류 신호 없는 실패 탐지 |
| **Structured Output** | SO-1 평면 구조 · SO-3 enum 준수 · SO-4 정의되지 않은 키 · SO-5 null 처리 | 스키마 준수 |
| | SO-7 한국어 수치 변환 · **SO-9 개인정보 마스킹** | 한국 도메인 |

**기준일을 시스템 메시지로 고정한다**(`2026-08-06`).
상대 날짜의 정답이 실행일에 따라 달라지면 재현할 수 없다.

정답 판정이 갈릴 수 있는 케이스는 `ambiguous=True`로 표시하고 집계에서 분리한다.

## 8. 실행 환경 필수 요구사항

측정 결과 자체를 왜곡할 수 있는 항목들이다.

| # | 요구사항 | 지키지 않을 경우 |
|---|---|---|
| H1 | **모든 테스트 데이터를 NFC로 정규화**하고 CI에서 검증한다 | NFD 형태의 한글은 토큰이 **8.5배**로 늘어난다. 화면상 구분되지 않으며 Python에서 문자열이 일치하지 않는다 |
| H2 | **`json.dumps(..., ensure_ascii=False)`를 사용**한다 | Python 기본값이 `True`라 한글이 이스케이프되어 토큰이 **3.15배**로 늘어난다 |
| H3 | 추론을 껐다고 기록한 조건은 **`completion_tokens`로 사후 검증**한다 | 요청이 200을 반환했다고 파라미터가 적용된 것은 아니다 |
| H4 | OAuth 토큰이 **만료되면 갱신 후 재시도**한다 | 토큰 수명(약 1시간)이 실행 시간보다 짧을 수 있다 |
| H5 | 인증 만료와 **권한 거부를 구분**한다 | 권한 문제에서 CLI를 불필요하게 반복 호출하게 된다 |
| H6 | `finish_reason == "length"`를 **조건별로 집계**한다 | 토큰 예산 부족을 성능 차이로 잘못 해석하게 된다 |
| H7 | 재시도를 **인프라 오류에만 적용**하고, 형식 오류는 재시도하지 않으며 전건을 기록한다 | 재시도가 실패를 가린다 |
| H8 | **모델을 교대로 호출**한다 | 공유 엔드포인트이므로 시간대에 따른 부하 차이가 결과에 반영된다. 추가 비용 없이 적용할 수 있는 통제 방법이다 |
| H9 | **실험 조건별로 동시 요청 수 상한을 따로 설정**한다 | GLM 5.2의 시간당 요청 한도가 7,200건(초당 2건)으로 나머지 두 모델의 1/50이다 |
| H10 | `max_tokens`를 **필요한 만큼만 설정**한다 | Databricks는 실제 출력이 아니라 **요청에 선언한 `max_tokens`로 분당 출력 토큰 한도를 차감**한다 |

## 9. 한계

설계상의 한계만 적는다. 결과 해석의 한계는 [FINDINGS §9](./FINDINGS.md).

- **enum 순서와 도구 정의 순서를 무작위화하지 않았다.** 위치에 따른 선택 편향 미통제.
- **단일 호출이다.** 1차 시도의 정확도를 측정하며 에이전트 반복 실행이 아니다.
- **게이트웨이 제약은 릴리스마다 바뀐다.** 실행할 때마다 §2를 다시 수행한다.
- **§3의 플랫폼 오작동은 수정되면 사라질 수치다.**
