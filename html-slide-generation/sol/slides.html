03 / 09

Core concept

The lakehouse architecture

A lakehouse unifies the low-cost, open storage of a data lake with the management and performance capabilities associated with a data warehouse.

Data lake strengths All data types · open formats · scalable object storage
Data warehouse strengths Reliable tables · SQL performance · governance · BI semantics
↓
Databricks Lakehouse Platform Engineering, streaming, SQL analytics, ML, and AI on one governed data foundation
↓
Cloud object storage + open table formats

The result is not one giant compute cluster: storage and compute are separated, so each workload can scale independently.

Lakehouse = lake flexibility + warehouse reliability
04 / 09

Data + compute foundation

Delta Lake makes lake data dependable

Delta Lake is the open table layer that adds ACID transactions on the lake, turning cloud files into reliable, queryable tables.

  • ACID transactions: concurrent reads and writes remain consistent.
  • Schema enforcement and evolution: control change without freezing it.
  • Time travel: query or restore earlier table versions.
  • Batch and streaming: use the same table for both patterns.
Delta transaction log Table versions · metadata · atomic commits
Open columnar data files Typically Parquet files in cloud object storage
Apache Spark / distributed compute Parallel processing for ETL, streaming, SQL, and ML workloads

Apache Spark is a core distributed compute engine in Databricks; the platform also adds optimized runtimes, managed compute, and serverless options.

Reliable tables on open cloud storage

Unity Catalog governs data and AI assets

Unity Catalog provides a common governance model across workspaces and workloads—from files and tables to functions, notebooks, and models.

Access control Central permissions at catalog, schema, table, view, row, and column levels.
Discovery Searchable metadata and business context help users find trusted assets.

AI

Foundation Model API (FMAPI)

The Foundation Model API exposes hosted foundation models through familiar APIs, enabling teams to prototype and serve generative AI without managing model infrastructure.

  • Use pay-per-token endpoints or provisioned throughput.
  • Call supported third-party or open models.
  • Combine models with governed lakehouse data for RAG and agents.

Mosaic AI is the platform capability set for developing, evaluating, governing, and deploying machine learning and generative AI applications.

09 / 09

In summary

Databricks is a governed platform for data and AI

1

Lakehouse architecture: combines data lake openness and economics with data warehouse reliability and performance.

2

Shared foundation: Delta Lake, Apache Spark and elastic compute support engineering, Databricks SQL, analytics, and machine learning.

3

Unified governance: Unity Catalog centralizes access control, discovery, auditing, and lineage for data and AI assets.

4

Production operations: Mosaic AI, the Foundation Model API, and Workflows move pipelines and AI applications from development to operation.

5

Multi-cloud: organizations can deploy Databricks on AWS, Azure, or GCP while keeping data in their chosen cloud environment.

The practical question is not “lake or warehouse?”—it is which workloads benefit from sharing one governed data foundation.
