Why it exists

The problem it was built to solve

Modern data stacks split work across many systems: a data lake for cheap storage, a warehouse for SQL analytics, a separate cluster for ML, and more for governance. Each is its own silo — duplicating data, slowing pipelines, and fragmenting security.

  • Data lakes are cheap and flexible — but lack reliability: no ACID guarantees, no schema enforcement, no fast BI.
  • Data warehouses are fast and governed — but expensive at scale, closed formats, and awkward for ML on unstructured data.
  • AI/ML sits apart from BI — so data teams copy and convert data repeatedly between systems.
  • Governance is fractured — different access rules per tool, no unified lineage or audit trail.
02 · The Problem
Architecture

The Lakehouse: lake + warehouse in one

Databricks pioneered the Lakehouse — an architecture that puts reliable, transactional table formats directly on top of cheap cloud object storage, so one copy of the data serves BI, engineering, and ML.

Data Lake

  • Cheap object storage
  • Open, any format
  • No transactions
  • Slow for BI

Data Warehouse

  • Fast SQL & BI
  • ACID + governance
  • Closed, expensive
  • Weak for ML

Lakehouse

  • Open storage + ACID
  • BI + ML on same data
  • One governance model
  • Works on any cloud
03 · Lakehouse Architecture
Storage layer

Delta Lake: ACID transactions on the lake

Delta Lake is the open-source storage format that makes the Lakehouse work. It adds a transaction log on top of Parquet files, bringing warehouse-grade reliability to data lake storage.

Reliability

ACID transactions

Concurrent readers and writers stay consistent. Schema enforcement and schema evolution prevent corrupted tables — no more "it worked yesterday" surprises.

Performance

Time travel & Z-ordering

Query any prior version of a table, roll back bad writes, and physically cluster data so filters prune files instead of scanning everything.

Openness

Open format

Parquet files plus a JSON transaction log. You're never locked in — other engines that speak Delta can read the same data directly.

Streaming

Unified batch + streaming

The same Delta table serves batch jobs and Structured Streaming upserts, so pipelines stay simple as volume grows.

04 · Delta Lake
Compute engine

Apache Spark: the distributed compute core

Databricks was founded by the original creators of Apache Spark, and Spark remains the engine powering large-scale ETL, batch, and streaming workloads on the platform. Databricks runs and manages it for you.

  • Distributed in-memory processing across a cluster — handles terabyte-scale transforms that a single machine never could.
  • One engine, many workloads: batch ETL, Structured Streaming, interactive notebooks, and ML training all share the same runtime.
  • Multi-language: write the same job in Python, SQL, Scala, or R notebooks — and reuse libraries from each ecosystem.
  • Managed for you: Databricks handles cluster provisioning, autoscaling, and the Spark runtime — including Photon, its vectorized C++ engine for faster SQL and DataFrame workloads.
05 · Apache Spark
Analytics

Databricks SQL: warehouse-grade analytics on the lake

Databricks SQL (DBSQL) is a serverless, ANSI-compliant SQL engine that lets analysts query Lakehouse data with the performance and tools they expect from a cloud data warehouse — without moving or copying it.

Interface
Web SQL editor & BI connectors
Built-in editor, dashboards, alerts, plus connectors for Tableau, Power BI, Looker and more.
Compute
Serverless SQL warehouses
Auto-start/stop, auto-scaling SQL clusters — pay only while queries run.
Engine
Photon vectorized execution
C++ rewrite of the Spark execution layer for low-latency, high-concurrency BI workloads.
Data
Delta Lake tables
Same governed data your engineers and ML teams use — no separate warehouse copy.
06 · Databricks SQL
Governance

Unity Catalog: one governance layer for everything

Unity Catalog is Databricks' unified governance solution — a single place to define who can access what, across all data, code, models, and AI assets in the platform.

Access control

Centralized permissions

Role-based, attribute-based access enforced consistently across SQL, notebooks, jobs, and models — with row- and column-level security.

Lineage

Automatic data lineage

Visual end-to-end lineage: trace any dashboard or model back to its source tables, columns, and upstream pipelines.

Audit

Audit & compliance

Complete audit log of who accessed or changed what — supporting SOC 2, HIPAA, GDPR, and similar regimes.

  • One namespace across all your workspaces and clouds — catalog → schema → table, with the same model applied to files, notebooks, and registered models.
07 · Unity Catalog
AI & Machine Learning

Mosaic AI: from classical ML to Foundation Models

Mosaic AI is the platform's unified ML/AI suite — everything from experiment tracking and managed model training to serving generative models, all integrated with the same governed Lakehouse data.

Training

Managed ML lifecycle

MLflow-based experiment tracking, feature engineering, managed model registry, and distributed training on Spark clusters.

Serving

Model serving

Real-time and batch endpoints for classical and deep-learning models, with auto-scaling and GPU support.

GenAI

Foundation Model API (FMAPI)

Pay-per-token access to leading open large language models (e.g., Llama, Mistral) — plus fine-tuning, RAG, and agent tooling to build LLM apps on your own enterprise data.

Governance

AI governance

Models, prompts, and evaluations are first-class assets in Unity Catalog — tracked, permissioned, and audited like data.

08 · Mosaic AI & FMAPI
Orchestration

Workflows: orchestrate the whole pipeline

Databricks Workflows is the built-in job orchestrator — schedule and chain notebooks, SQL statements, Python scripts, ML training, and model deployments into reliable, observable pipelines — no separate Airflow needed for platform-native jobs.

  • DAG-based scheduling: define task dependencies, retries, conditional branches, and SLA-driven triggers across notebook, SQL, Python wheel, and model tasks.
  • Multiple triggers: run on a schedule, on file arrival, continuously as a stream, or via REST API from external systems.
  • Built-in observability: per-task status, run history, logs, and automatic notifications on failure — visible in the same UI as the data.
  • Reuses compute: jobs run on the same managed clusters/serverless as interactive work — no duplicate infra to operate.

Deployment & Summary

Runs on every major cloud — and your data stays yours

Azure

Tight first-party integration as Azure Databricks — linked to your Azure subscription, ADLS, and Active Directory.

GCP
